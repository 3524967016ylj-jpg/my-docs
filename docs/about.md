# 关于本项目

## 1. 项目背景

本项目是《开源软件构建技术理论与实践》课程的个人实践项目，主要任务是搭建一个基于 MkDocs Material 的静态文档网站，并通过 GitHub Actions 实现自动构建和部署，最终使用 GitHub Pages 发布网站。

在开始本次实践之前，我对 Git、GitHub 和开源软件协作流程的了解还比较有限。通过本次实践，我希望逐步掌握版本管理、文档编写、自动化构建和网站部署等基本技能。

## 2. 项目目标

本项目主要实现以下目标：

- 使用 Markdown 编写结构清晰的技术文档。
- 使用 Git 管理项目文件和版本变化。
- 使用 GitHub 托管项目源码。
- 使用 MkDocs Material 将 Markdown 文档构建为静态网站。
- 使用 GitHub Actions 实现自动化构建和部署。
- 使用 GitHub Pages 发布网站，实现公开访问。

## 3. 技术组成

本项目主要使用以下技术和工具：

| 技术或工具      | 主要作用                             |
| --------------- | ------------------------------------ |
| Git             | 管理项目版本，记录文件修改历史       |
| GitHub          | 托管项目源码，支持远程协作           |
| Markdown        | 编写网站中的技术文档                 |
| Python 3.12     | 提供 MkDocs 的运行环境               |
| MkDocs Material | 将 Markdown 文档构建成静态网站       |
| GitHub Actions  | 自动执行依赖安装、网站构建和部署任务 |
| GitHub Pages    | 托管构建完成的网站，提供公开访问地址 |
| Typora          | 编辑和预览 Markdown 文档             |

## 4. 系统工作流程

本项目的整体工作流程如下：

1. 在本地使用 Typora 编写和修改 Markdown 文档。
2. 使用 Git 对修改内容进行版本管理。
3. 将本地提交推送到 GitHub 仓库的 main 分支。
4. GitHub Actions 自动检测代码变化并执行构建任务。
5. MkDocs 将 docs 目录中的文档生成静态网站文件。
6. GitHub Actions 将生成的网站部署到 GitHub Pages。
7. 用户通过浏览器访问最终发布的网站。

核心命令示例：

```bash
# 构建静态网站
py -3.12 -m mkdocs build --strict

# 启动本地预览
py -3.12 -m mkdocs serve
```

## 5. 实践体会

通过前期的环境准备和仓库克隆，我初步理解了本地仓库与远程仓库之间的关系。

在实际操作中，我曾遇到 Git 无法连接 GitHub 的问题。通过检查网络连接和执行 git ls-remote 命令，我逐步定位了问题，并最终成功完成仓库克隆。

这让我认识到，Git 不仅仅是上传和下载代码的工具，还能够帮助开发者管理项目版本、追踪修改记录。

目前已经完成四页文档、本地构建和首次 GitHub Actions 部署。下一步通过再次修改文档并推送，验证网站能否自动更新。
